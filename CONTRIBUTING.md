# Contributing

## Branch first

Create and switch to a task-specific branch before adding, editing, moving, or deleting content. Do not make content changes directly on `main`.

Work in one explicitly identified client repository at a time. Never propagate a change to similarly named workshop repositories automatically.

## Public safety

Before committing, confirm that the change contains no:

- client-confidential or proprietary information;
- personal names, contact details, credentials, or private URLs;
- internal planning notes or private deliverables;
- files copied from the parent workspace's `sources/`, `reference/`, `instructions/`, or `output/` folders.

Use fictional or generalized business scenarios unless publication of specific material has been approved.

## Exercise quality

- Keep instructions practical, hands-on, and encouraging.
- Use Thai where appropriate while retaining official English product names and UI labels.
- State paid-license requirements clearly.
- Use relative links for screenshots and sample files.
- Verify local links and Markdown formatting before committing.
